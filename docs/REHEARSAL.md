# 교실 2대 왕복 리허설 절차

> **이 문서의 목적**: 실기기에서만 확인되는 것을 현장에서 헤매지 않고 통과시킨다.
> 코드로 검증 가능한 것은 전부 자동 테스트가 덮고 있으므로(단위·위젯 114 + 통합 1),
> **여기 남은 항목은 "실기기·실네트워크가 아니면 알 수 없는 것"뿐**이다.
>
> ⚠️ 자격증명(교사 계정·참여코드·게이트웨이 비번)은 이 문서에 적지 않는다 — 저장소가 공개다.
> 로컬 메모리(`project_chominjungum_app` / `project_chominjungum_web`)를 참조한다.

---

## 0. 왜 실기기가 필요한가 — 남은 4가지

| 항목 | 왜 시뮬레이터로 안 되나 |
|---|---|
| **iOS 로컬 네트워크 권한 프롬프트** | 시뮬레이터에는 이 제약이 **아예 없다**. 2026-09-07 에 `NSLocalNetworkUsageDescription` 이 빠져 있던 것도 그래서 모든 검증을 통과했다 |
| **카메라 QR 스캔** | 시뮬레이터에 카메라가 없다(지금까지 페이로드 붙여넣기로 우회했다) |
| **기기 간 LAN 도달성** | `NetworkInfo` 가 준 IP 가 **다른 기기에서 실제로 열리는가**. 통합 테스트는 루프백을 쓴다 |
| 손글씨 터치 입력 품질 | 마우스 드래그와 손가락은 다르다 |

## 1. 🔴 가장 먼저 확인할 것 — 그 Wi-Fi 가 단말 간 통신을 허용하는가

**회사·학교 Wi-Fi 는 클라이언트 격리(AP isolation / client isolation)를 켜 둔 경우가 많다.**
켜져 있으면 같은 SSID 에 붙어 있어도 **기기끼리 패킷이 오가지 않는다** — 이 앱은 그 위에서
동작하므로 아무리 코드가 맞아도 연결이 안 된다. 원인을 앱에서 찾다가 시간을 다 쓰기 쉽다.

**1분 판정** (두 기기를 같은 Wi-Fi 에 붙인 뒤):

```bash
# 맥에서 — 학생 기기 IP 로 ping (IP 는 기기 설정 > Wi-Fi > 상세)
ping -c 3 <상대 기기 IP>
```

- 응답 있음 → 통과. 2절로.
- 100% loss → **격리된 망이다.** 아래 중 하나로 우회:
  1. **개인 핫스팟** — 교사 기기(또는 다른 폰)로 핫스팟을 켜고 두 기기를 거기에 붙인다.
     가장 확실하고 교실에서도 쓸 수 있는 방법이다.
  2. 게스트망이 아닌 사내망 — 격리는 보통 게스트 SSID 에만 걸려 있다
  3. 집 Wi-Fi 에서 재시도

> 교실 배포에서도 같은 문제가 생길 수 있다. **학교 Wi-Fi 가 격리돼 있으면 이 앱의 전제가
> 무너진다** — 그때는 교사 기기 핫스팟이 정답이고, 그 사실을 사용 안내에 넣어야 한다.

## 2. 설치 — 역할이 엔트리로 갈린다

⚠️ **번들 ID 가 같아서(`com.chominjungum.chominjungum`) 한 기기에 하나만 깔린다.**
교사용과 학생용을 **따로 빌드해 각 기기에 설치**한다. 순서를 섞으면 두 기기에 같은
역할이 깔린 채로 "왜 QR 이 안 뜨지" 하게 된다(2026-09-07 에 실제로 겪었다).

```bash
cd apps/chominjungum
flutter devices          # 기기 UDID 확인

# ── 교사 기기
flutter build ios --release -t lib/main_teacher.dart
xcrun devicectl device install app --device <교사 UDID> \
  build/ios/iphoneos/Runner.app

# ── 학생 기기
flutter build ios --release            # 기본 타깃 = lib/main.dart (학생)
xcrun devicectl device install app --device <학생 UDID> \
  build/ios/iphoneos/Runner.app
```

⚠️ **`--release` 필수.** 디버그 빌드는 단독 실행 시 흰 화면으로 죽는다(워크스페이스 공통 함정).
⚠️ **무료 프로비저닝은 7일 만료.** 리허설 직전에 다시 설치할 것.

첫 실행 때 기기에서 개발자 신뢰가 필요하면:
설정 > 일반 > VPN 및 기기 관리 > 개발자 앱 > 신뢰.

## 3. 왕복 시나리오 — 순서대로, 각 단계에서 멈춰 확인

| # | 조작 | 확인할 것 | 어긋나면 → 5절 |
|---|---|---|---|
| 1 | 교사 앱 실행 → **허브 시작** | ⭐**로컬 네트워크 권한 프롬프트가 뜨고 "허용"** · QR 표시 · IP 가 자기 Wi-Fi 대역인지 | A, B |
| 2 | 학생 앱 실행 → QR 스캔 | ⭐**카메라 권한 프롬프트** → 스캔 즉시 "허브에 연결됨" | C |
| 3 | 교사 화면 | "접속 학생 1명" | D |
| 4 | 교사: 문장 입력 → **문제 전송** | 학생 화면이 **자동으로 받아쓰기로 열린다** · 칸 수가 문장 글자 수와 같다 | E |
| 5 | 학생: 손글씨 → 앱바 ✅ → 답 입력 → **채점** | 점수·글자별 ✓/✗ · 틀린 글자에 `쓴 것 → 정답` | — |
| 6 | 학생: **선생님께 제출** | 교사 "제출 현황"에 1건 · 점수·평균 | D |
| 7 | **양쪽 앱을 완전 종료 후 재실행** | 교사: 지난 수업 이력 남아 있음 · 학생: 받은 문제 그대로 | F |
| 8 | (선택) 교사: 서버 주소·토큰·학급 입력 → **지금 올리기** | "업로드 완료 — 신규 N건" | G |

각 단계에서 **화면을 사진으로 남겨** 두면 나중에 원인 추적이 쉽다.

## 4. 8번(서버 업싱크)에 대한 주의

**LAN 직결 주소도, 외부 주소도 된다.**

2026-09-07 까지는 외부 주소가 401 이었다 — 게이트웨이가 HTTP Basic 을 요구하는데 앱은
그 자격을 보낼 수 없었기 때문이다. **2026-09-08 에 업싱크 경로 하나만 게이트 밖으로
빼고 서버 JWT 로 지키도록 바꿨다**(`PLAN.md §11`). 그 뒤 실측으로 외부 주소 업싱크가
성공하는 것을 확인했다.

교사 토큰은 **웹 콘솔에서 로그인해 복사**해 앱에 넣는다(로그인 경로는 게이트 뒤에 그대로다).
그래도 인터넷이 없으면 Hive 큐가 보관하므로, 나중에 올려도 수업 결과는 사라지지 않는다.

## 5. 진단 — 증상에서 원인으로

**A. 허브 시작이 실패한다 / IP 가 비어 있다**
- 프롬프트를 "허용 안 함" 했다면: 설정 > 초민정음 > **로컬 네트워크** 켜기
- IP 가 안 잡히면 교사 화면 "허브 IP" 칸에 직접 입력(기기 설정 > Wi-Fi > 상세에서 확인)
- `address already in use` → 이전 인스턴스가 살아 있다. 앱 완전 종료 후 재실행

**B. 프롬프트가 아예 안 뜬다**
- 이미 한 번 응답했으면 다시 뜨지 않는다. 설정에서 직접 확인
- 앱을 삭제하고 재설치하면 프롬프트가 초기화된다

**C. QR 을 스캔해도 반응이 없다**
- 카메라 권한 확인
- QR 이 화면 밝기·각도 때문에 안 읽히면 → 교사 화면 **"연결 정보 보기 (QR을 못 읽을 때)"**
  로 문자열을 펼쳐 학생 화면 "페이로드 붙여넣기"에 넣는다(설계된 대체 경로)
- ⚠️ 그 문자열에는 **세션 키가 들어 있다.** 학생 기기에만 보여주고 끝나면 접는다

**D. 연결은 됐는데 접속 수·제출이 안 보인다**
- 세션 키 불일치 → 교사가 허브를 재시작했다면 학생도 다시 스캔해야 한다(QR 이 바뀐다)
- 학생이 다른 교사 세션에 붙어 있지 않은지

**E. 문제 전송이 실패한다**
- `출제 실패: …` 가 뜨면 문장에 허용 밖 문자가 있다(한글·숫자·공백·`. , ? !` 만)
- ⚠️ **네트워크 오류 문구가 뜨면 회귀다** — 출제는 기기에서 분해해야 한다.
  2026-09-07 에 원격 서버 의존을 제거했고 테스트가 지키고 있다

**F. 재실행 후 이력이 사라졌다**
- Hive 영속화 회귀다. `test/dictation_repository_test.dart`·`local_store_test.dart` 확인
- ⚠️ 통합 테스트(`integration_test`)를 실기기에 돌리면 **끝에 `LocalStore.clearAll()` 로
  기기 이력을 지운다.** 리허설 데이터를 남겨야 하면 리허설 전에 돌리지 말 것

**G. 업싱크가 401/400 이다**
- **401 + JSON(`로그인이 필요합니다`)** → 앱 토큰 문제다. 교사 토큰은 12시간 만료 —
  웹 콘솔에서 다시 로그인해 복사한다
- **401 + `WWW-Authenticate: Basic`** → 게이트웨이가 막은 것이다. 업싱크 경로 예외가
  풀렸는지 확인(`.25` nginx `location = /chominjungum/api/sync/sessions`)
- 400 → 학급 ID 가 UUID 인지 확인. 서버는 `sessionId`·`classroomId`·`attemptId` 를 UUID 로 검증한다
